## 1. Главный продуктовый вывод

Проблема с дублированием реальна.

Сейчас предметы и семестры представлены сразу в нескольких местах:

1. **«Инфо»**
   - учебный профиль;
   - текущий и другие семестры;
   - предметы по формам контроля;
   - переход в подробную карточку предмета.
2. **Профиль → «Текущий семестр» → «Зачёты и экзамены»**
   - текущий семестр;
   - полный учебный план;
   - предметы по формам контроля;
   - сложность;
   - чат;
   - экспорт PDF.
3. **«Обучение»**
   - команды предметов;
   - чаты;
   - задания и файлы.
4. **«Мой дневник»**
   - личные задачи;
   - задания;
   - заметки, конспекты и файлы по предметам.

Само наличие этих возможностей правильно. Ошибка не в функциях, а в том, что пользователь не понимает, **какой раздел является главным источником правды о предмете**.

### Принятое направление

- **«Информация»** — узнать всё о семестре, предмете и преподавателе.
- **«Обучение»** — действовать: чат, задания, файлы, команды. На ближайшем этапе раздел не меняется.
- **«Расписание»** — понять, что и когда происходит.
- **«Главная»** — увидеть главное на сегодня.
- **«Профиль»** — управлять собой, друзьями, настройками и доступом.

Учебный план остаётся внутри «Информации». PDF отложен: в первой цельной версии он не нужен, не должен занимать место в интерфейсе и не является блокером релиза. Существующий внутренний код экспорта пока не удаляем, но новые работы вокруг PDF не планируем.

## 8. Постоянное пространство учебной группы

### Продуктовое решение

На первом этапе не давать студентам свободно создавать множество команд. Для каждой учебной группы автоматически создаётся **одно постоянное пространство группы**, которое не связано с отдельным предметом и не закрывается при смене семестра.

- [ ] одна группа → одна постоянная команда/пространство;
- [ ] один основной групповой чат без привязки к предмету;
- [ ] автоматическое добавление действующих студентов группы;
- [ ] автоматическое исключение или архивирование участника после перевода/отчисления;
- [ ] пространство продолжает жить при переходе на новый семестр;
- [ ] уникальность гарантируется на сервере, чтобы не появлялись дубли;
- [ ] произвольное создание дополнительных команд отложить;
- [ ] возможность второй специальной команды оставить как будущую настройку администратора, только если появится реальный сценарий.

### 8.1 Сбор группы

Это учёт договорённостей, а не приём платежей внутри приложения.

- [ ] организатор создаёт сбор: название, описание, срок, необязательная целевая сумма;
- [ ] участник отмечает `Скинул`;
- [ ] участник может приложить подтверждающий скриншот;
- [ ] статус участника: `Не отмечено` / `На проверке` / `Подтверждено`;
- [ ] организатор подтверждает отметку;
- [ ] вся группа видит общий прогресс и статусы;
- [ ] подтверждающий скриншот по умолчанию видят только участник и организатор;
- [ ] редактирование и закрытие сбора;
- [ ] журнал изменений;
- [ ] push только по важным событиям, без спама;
- [ ] не хранить банковские карты и не проводить деньги через приложение.

### 8.2 Выбор темы

- [ ] организатор создаёт выбор и список тем;
- [ ] у темы задаётся вместимость: один человек или несколько;
- [ ] студент выбирает тему;
- [ ] сервер транзакционно запрещает занять последнее место одновременно двум студентам;
- [ ] выбранная тема сразу отмечается в Realtime;
- [ ] выбор можно изменить до установленного срока или блокировки организатором;
- [ ] организатор может закрыть выбор;
- [ ] видны свободные, занятые и выбранная пользователем темы;
- [ ] история изменений защищает от споров;
- [ ] возможность выгрузить итоговый список добавить только при подтверждённой необходимости.

## Appendix C — Короткий Definition of Done первой цельной версии *(исторический §16)*

Первая версия логически закончена, когда:

- студент понимает назначение каждой вкладки;
- предмет существует в одном основном информационном разделе;
- чат, дневник и расписание доступны как действия, а не копии каталога;
- профиль не содержит учебный портал и новостную ленту;
- администратор без SQL наполняет преподавателей, предметы, группы и семестры;
- данные можно проверить до публикации;
- прошлые семестры не смешиваются с текущим;
- постоянное пространство группы не зависит от семестра и не создаёт дублей;
- сбор группы и выбор темы работают как организационные инструменты, а не как платёжная система;
- отзывы безопасны или честно отключены;
- Android и iPhone проходят физический smoke;
- остаются только контентное наполнение и небольшие подтверждённые баги;
- управляемый контент (Главная / профиль / справочник / предметы / вакансии) редактируется без сырого JSON в UI;
- Import Studio даёт dry-run/diff до apply.
