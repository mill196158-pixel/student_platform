# Загрузка главной, профиля и запуск — 30.10.2026

## Исправления

- Главная больше не ждёт общий `Future.wait` перед показом интерфейса. Профиль, расписание, задания, новости и групповые дела запускаются независимо и обновляют общий снимок по готовности.
- Cached profile принимается только при совпадении с текущим ненулевым auth UID. Сохраняются уже показанные данные при refresh. Для незагруженного/ошибочного расписания и заданий есть отдельные подписи вместо ложного «ничего нет».
- До четырёх запросов заданий выполняются одновременно вместо последовательного обхода восьми команд. Для get_my_teams достаточно JWT: ожидание серверного профиля убрано.
- Метаданные новостей показываются до скачивания изображений. Home refresh объединяет одновременные вызовы только в рамках аккаунта; deadline 18 секунд освобождает повтор и отсекает поздние ответы.
- Профиль показывает проверенную локальную шапку до сетевого refresh сессии. Две рекламные карточки загружаются параллельно; image/icon стартуют одновременно и публикуются независимо. Используется существующий защищённый дисковый кэш с grant/TTL/account isolation.
- Firebase/local notifications больше не блокируют `runApp` и первый кадр. Single-flight предотвращает повторную инициализацию; ошибка допускает retry через host. Убран искусственный Splash delay 600 мс. Проверки входа/смены пароля не обходятся; initial-message обрабатывается после Firebase с captured-session guard перед stash.

## Измерения и их границы

Контролируемый тест держит profile/news RPC незавершёнными: cached dashboard snapshot появляется за **52–77 мс**. Проверено, что остальные секции начинают запросы до ответа профиля; результаты старого аккаунта не публикуются.

На установленной profile-сборке, реальная сохранённая сессия:

| Метрика | Результат |
|---|---:|
| Home: первый частичный snapshot от начала загрузки вкладки | 27 мс; повторный замер 42 мс |
| Profile: локальный boot | 7 мс |
| Profile: loading=false build после boot | около 143 мс |
| Profile: серверные счётчики | позднее, около 1,3 с; шапку не блокируют |
| Dart main → Supabase ready | 1858 мс |
| Dart main → local cache ready | 1895 мс |
| Dart main → first-frame callback | 2078 мс |
| Android am start -W, холодный процесс после startup change | 9975 мс |

До startup change профильная сборка дала 11308 мс, другой запуск закончился таймаутом ожидания 17469 мс. Debug baseline дал 12716 мс. Из-за разброса нагрузки эмулятора, компиляции на хосте и различий режима **процент ускорения не выводится**. 27–42 мс — время до первого частичного состояния уже открываемой главной, не время полного запуска приложения и не загрузка всей сети.

Сетевые картинки при первом отсутствии кэша по-прежнему зависят от сервера и соединения.
