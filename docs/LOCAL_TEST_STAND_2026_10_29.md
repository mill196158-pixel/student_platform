## Повторение

Создание пустого отдельного проекта выполнено через:

```powershell
npx --yes supabase@2.122.0 init --workdir C:\student_platform_e2e
# Изменить локальные порты 5432x на 5532x перед запуском.
npx --yes supabase@2.122.0 start --workdir C:\student_platform_e2e --exclude studio,postgres-meta,edge-runtime,logflare,vector,supavisor,imgproxy
```

`scripts/local_e2e_schema.py` работает только с контейнером
`supabase_db_student_platform_e2e`; при существующей users отказывается
неявно сбрасывать данные. Сброс общего Docker или production запрещён.
`scripts/local_e2e_api.py` принимает только API 127.0.0.1:55321, запрещает
редиректы и системный HTTP proxy; проверяет реальные HTTP-ответы и результаты.
При ошибках возвращает ненулевой exit code.

```powershell
python scripts/local_e2e_api.py
flutter test integration_test/local_social_test.dart -d emulator-5554 --dart-define-from-file=C:\student_platform_e2e\flutter-defines.json
```

UI-сценарий запускает реальные экраны в тестовой оболочке, без Firebase и
production main. Это экранная интеграция, не полный cold-start приложения.
Без явного локального URL/ключа/пароля тест немедленно завершается ошибкой.

## Дополнительно разрешённый live-прогон

Владелец затем прямо разрешил использовать основную базу. Созданы три отдельных
синтетических аккаунта с уникальным префиксом e2e_, маркером запуска и приватным
manifest вне репозитория. `scripts/approved_live_regression.py` требует явного
`--approved`, поддерживает подготовку, проверку и уборку только своих UUID.
Пароли и ключи не входят в коммит. Не использовать этот runner как регулярный
production cron: он предназначен для явно разрешённой диагностической сессии.

Первый прогон: **29/30**. Обнаружена реальная уязвимость:
`toggle_message_reaction` позволяла постороннему менять реакции чужого сообщения
по известному UUID. Чтение/отправка в чужой чат уже отклонялись.

Миграция `20261029193351_enforce_reaction_chat_membership.sql` добавляет
проверку видимости целевого чата до чтения/изменения реакций, фиксирует
search_path и закрывает PUBLIC/anon EXECUTE. Доступ участников и одногруппников
учебного чата соответствует существующему get_chat_messages_page.
Существующий архивный trigger не менялся.

До применения проведена транзакционная репетиция с ROLLBACK на основной базе:
посторонний не меняет строку/кэш, участник добавляет/меняет/удаляет реакцию,
доступ по членству и группе сохранён, архив отклоняет изменение, grants корректны.
Независимый reviewer APPROVE. После применения обычные клиентские сессии:
**30/30 PASS**, anon EXECUTE false, authenticated true, архивный trigger на месте.

Android `approved_live_social_test.dart`: **PASS**, ~48 секунд после установки.
Реальные нажатия в профиле другого пользователя, заявка, принятие второй сессией,
возврат и список друзей; изменение статуса в настройках и повторное открытие.
Оболочка экранного теста не запускает Firebase; это не полный cold-start.

Отдельные сценарии чата и полного запуска имеют самостоятельные результаты;

## Дополнительные ошибки реального Android-прогона

DM-композер показывался до окончания проверки блокировки/восстановления черновика.
Раннее нажатие молча игнорировалось, а восстановление могло перезаписать ввод.
Добавлена готовность после черновика и ForwardOutbox, загрузка/повтор при ошибке,
повтор инициализации после разблокировки. Необязательная история/receipts не
блокирует готовое поле. Отправка после этой правки дошла до второго участника.

Следующий этап обнаружил отказ прямого RLS-чтения сообщения: permission denied
for function is_group_space_member. Пять private boolean helpers, используемых
в политиках, не имели authenticated EXECUTE. Миграция
`20261029194910_restore_authenticated_rls_helper_execution.sql` выдаёт это
право ровно пяти функциям; anon/PUBLIC остаются закрытыми, политики не меняются.
Репетиция с SET LOCAL ROLE authenticated + JWT и ROLLBACK: участник видит
сообщения, outsider не видит ни одного. После применения у всех пяти функций
anon=false/authenticated=true. Независимое ревью APPROVE_WITH_NOTES.
Повторный API-прогон с точными проверками отказов: 30/30 PASS.
Корневые unit/widget тесты после изменения: 315 PASS.

Первый cold-start navigation прогон: вход успешен, Главная отрисована, затем
нажатие перекрыл штатный push pre-permission sheet. Сценарий дополнен
