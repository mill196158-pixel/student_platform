## Как устроить приложение для студента

Одна сборка, четыре постоянные вкладки. Существующие личные функции сохраняются. Публичный режим добавляется отдельным потоком; он ещё не реализован.

| Вкладка | Первый экран и переходы | Гость | После входа |
|---|---|---|---|
| Учёба | Поиск → предмет → тема → пример/материал → просмотр/скачивание | Опубликованные материалы и локальные закладки | Мои предметы, задания, дневник |
| Расписание | Выбор группы → неделя/день → занятие | Публично разрешённое расписание; выбор хранится локально | Личные заметки и напоминания |
| Сервисы | Категории → калькулятор/шаблон/инструкция | Без регистрации | Персональные сохранения при необходимости |
| Моё | Избранное и настройки → вход | Локальное избранное, тема, история | Профиль → группа/друзья/сообщения; закрытая бета |

Общий поиск охватывает материалы; поиск людей остаётся отдельным после входа. Одна карточка предмета объединяет материалы, занятия и личные задания. Не создавать дубли этих данных в нескольких независимых разделах.

## Порядок выполнения и критерии

1. P0: права API/объектов, дубли отправки, утечки при смене аккаунта.
2. P1: реальные вложения, отмена/повтор/очистка; OCR без сети; offline→online.
3. P1: каждый экран ниже — загрузка, главное действие, проверка сохранения, назад, ошибка/повтор.
4. P1: учебные роли на изолированных командах/заданиях; конфликт двух участников.
5. P2: адаптация/клавиатура/пустые данные; release-сборка; физическое устройство/push.

Статусы отдельно: **экран открыт**, **действие проверено**, **результат в БД подтверждён**, **отказ/ошибка проверены**. Статический импорт тестом не является доказательством выполнения. Предыдущие результаты — в LOCAL_TEST_STAND_2026_10_29.md; текущие сценарии будут отмечаться по факту.

## Неэкранные сценарии

| Сценарий | Проверка результата |
|---|---|
| OCR | Русский текст из PNG; пустой/повреждённый вход; большой bitmap; PDF; ручное исправление до публикации |
| Файл | PNG/PDF/TXT → upload → запись → сообщение → второй участник скачивает те же байты; постороннему отказ |
| Отмена файла | Во время PUT и после загрузки; нет ложного attached; метаданные и объект очищаются |
| Offline | Загруженная история читается; отправка не теряется; retry не дублирует; кэш не переходит другому аккаунту |
| Права | Гость/участник/посторонний/староста/админ; прямой API и URL объекта |

## Результаты текущего расширенного прогона

- Android native OCR: до изменения native-кода PASS без Wi-Fi/mobile data; после ограничения bitmap повторный PASS, 4 с с включённой сетью. Три русские темы, пустой/битый вход и белая картинка. Большой допустимый bitmap и граничные50 МП ещё не проверены.
- Вложение: presign участник 200 / посторонний 403; PUT и GET синтетических32 байт PASS. Найден P1: прямой URL доступен без авторизации. Синтетический объект удалён: DELETE 204, подписанный GET 404. Закрытие публичного доступа ещё не выполнено; существующие потребители прямых URL требуют миграции.
- DM: исправлен повторный INSERT после сбоя. Новый идемпотентный RPC применён; Android PASS: offline→retry, потеря ответа после commit→retry, ошибка hydration, смена аккаунта во время ACK. Во всех сценариях одна серверная запись; чужой кэш не появляется.
- Лимиты файлов: пустой и >100 МБ отклоняются до чтения/сети, unit PASS. OCR: ограничение8 МБ / 50 МП, downsample до12 МП; повторный Android OCR PASS после исправления.
- Смешанные вложения: исправлено повторное отображение фото/документа; regression PASS.
- Форма сбора: добавлена защита от тихой потери выбранного файла. С файлом RPC не вызывается, после удаления файла попытка публикации доступна; regression PASS. Полноценная загрузка вложений сбора НЕ реализована.
- Android: ArchiveScreen, MyVacancySubmissionsScreen, ProposeVacancyScreen, CreateCollectionScreen, CreateTopicSelectionScreen, TopicListReviewScreen — открытие/прокрутка/ввод PASS, 59 с. Публикация, роли и сохранение на этих экранах этим тестом не проверялись.
- Offline: persisted clearedAt сохраняется при сбое загрузки настроек; следующий запрос повторяет fetch. Android transport suite PASS, 26 с вместе с lostACK/retry/hydration/accountswitch.
- Основная база: повторный API-прогон 30/30; синтетические пользователи/чаты удалены. Временный storage-access-audit отключён: HTTP 410, без импорта signing-кода и доступа к секретам.

## Следующий этап: что нужно завершить до заявления «весь функционал проверен»

1. **Файлы, P1:** сохранить текущие настройки public access; проверить подпись скачивания с реальными правами участника/постороннего и отдельными правилами платёжных доказательств. Проверить происхождение file_key в save_chat_file, чтобы подставленная метаинформация не давала доступ к чужому объекту. Перевести изображения, галереи, PDF, скачивание, пересылку и кэш на новый доступ. Проверить canary, затем ограничить chats/* с проверенным rollback. Старые APK с прямыми URL должны получить обновление.
2. **Вложения:** отмена PUT/после PUT, удаление неотправленного файла, атомарная привязка к сообщению и очистка сирот; PDF/фото/TXT на втором аккаунте; истечение ссылки; offline-кэш между пользователями. Вложения сбора реализовать отдельным атомарным потоком, затем убрать временную защиту.
3. **Учебные роли:** синтетические группа/offering/team/enrollment, роли участника/старосты/постороннего. Для строк 21–33 пройти создание, изменение, конфликт, чтение другим участником и отказ постороннему. Не публиковать тестовые материалы реальной группе.
4. **Дневник и расписание:** реальные маршруты занятия, текста, фото; сохранить→перезапустить→прочитать→изменить→удалить; camera/gallery на устройстве; чужая запись недоступна.
