## Подтверждённые исправления этого прохода

- **P1, задания / основная БД:** `remove_assignment` позволяла постороннему удалить запись по UUID. `update_assignment` также не проверяла автора/участие; `set_assignment_done` не проверяла членство. Применены миграции `20261030003733_assignment_mutation_authorization.sql` и `20261030004549_assignment_rpc_only_writes.sql`: автор/руководитель и активное членство для изменения/удаления, активное членство и опубликованное задание для выполнения, отказ anon, пустой search_path. Прямые записи в assignments/assignment_done (включая column grants) закрыты; чтение и service_role сохранены. Проверка до применения: rollback-only SQL harness в отдельной схеме локального Docker (контролируемая модель членства). Реальный helper дополнительно проверяется native REST-запросами.
- **Задания / экран:** поздний ответ Realtime после закрытия TeamCubit больше не вызывает `Cannot emit new states after calling close`. Ожидание ответа сервера перед успехом/закрытием, блокировка повторного запроса, явная ошибка сохранения. Исчезнувшее задание не заменяется другим из списка. Два widget-теста PASS.
- **Личный дневник:** нет полной белой перезагрузки после статуса; optimistic update, rollback ошибки, блокировка дубля, защита от устаревшего refresh и корректное принятие нового серверного статуса. Кэш не сохраняет ответ предыдущей сессии для другого пользователя.
- **Отзывы:** настройка сервера `text_enabled=false` скрывает поле и исключает текст из отправки. Native submit/edit/moderation/aggregation/outsider PASS.
- **Уведомления:** снятие прочитанного баннера, обновление счётчика при Realtime UPDATE/DELETE, очистка баннера и дедупликации при выходе. Отмена анимации не оставляет обработчик нажатия зависшим и не удаляет новый баннер.

### Дополнительные границы серверного аудита

Анонимные вызовы всех трёх защищённых RPC проверены на основной базе: HTTP 401. В SQL сохранена совместимость опубликованных legacy-заданий: непустой published_at также считается признаком публикации.

Supabase Advisors после миграции не показывает mutable search_path для этих трёх функций. Предупреждение об authenticated SECURITY DEFINER ожидаемо: это разрешённый API с внутренней проверкой прав. Общие предупреждения проекта не обнулены: остаются view `v_lessons_team_link` и таблицы без RLS; доступность каждой зависит также от GRANT, поэтому список Advisors сам по себе не доказывает открытую утечку. Это отдельный остаток полного аудита, не выданный за исправленный здесь: [RLS](https://supabase.com/docs/guides/database/database-linter?lint=0013_rls_disabled_in_public), [views](https://supabase.com/docs/guides/database/database-linter?lint=0010_security_definer_view).
