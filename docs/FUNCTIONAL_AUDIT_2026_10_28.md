## Найденные причины и исправления

1. Большинство первоначальных 15 падений root suite были ошибкой компиляции
   pdfrx_engine 0.4.4: nullable cache терял promotion после await в closure.
   Локальная совместимая копия пакета сохраняет final activeCache. Изменён один
   исходный файл; LICENSE сохранён. Обновление 0.4.6+ требует archive 4, который
   конфликтует с текущим excel/archive 3. Root и Admin используют одну копию.
2. Старые тесты ожидали «Выбор темы», хотя интерфейс уже использует
   «Создать список тем». Ожидания приведены к существующему продуктовому решению.
3. Старый тест расписания ожидал отображение неизвестного статуса, хотя рабочий
   mapper намеренно фильтрует непустые статусы, отличные от open. Для проверки
   отображения двух открытых событий fixture исправлен на open.
4. В saveChat удалён запасной вызов send_chat_message_for_login. Ошибка основной
   отправки теперь передаётся вызывающему коду; TeamCubit отмечает сообщение
   ошибкой, вместо выдачи локально сохранённого сообщения за доставленное.

## Подтверждённые угрозы серверных функций

Изучены текущие определения функций из pg_proc без вызова операций над
пользователями и сообщениями:

- upsert_local_user меняла пароль auth.users по переданному логину без проверки
  владельца (для аккаунтов legacy @app.local).
- send_test_message и send_chat_message_for_login подставляли автора из p_login,
  не проверяя соответствие текущему auth.uid().
- register_local_user напрямую создавала Auth-профиль, обновляла public.users
  по логину и добавляла в переданную группу. Клиентский вход при этом использует
  @student.local, а функция создавала @app.local.
- get_my_teams_by_login и debug_team_snapshot раскрывали сведения без проверки
  принадлежности вызывающего пользователя.

Все шесть функций были доступны anon. После разрешения владельца применена
миграция restrict_unsafe_legacy_rpcs: EXECUTE отозван у PUBLIC, anon,
authenticated для всех перегрузок указанных имён. Контрольный запрос:
functions=6, remaining_client_access=0. Данные и пароли не изменялись.
Первый вызов миграции завершился тайм-аутом истории; права перепроверены,
повторное применение подтвердило success и затем отсутствие доступа.

Самостоятельная legacy-регистрация временно закрыта понятным экраном получения
доступа. Безопасная самостоятельная регистрация с проверкой принадлежности
группе ещё не реализована. Это явное функциональное ограничение ради закрытия
подтверждённой угрозы, а не готовая замена регистрации.

## Незакрытые области

- RLS/IDOR для authenticated на старых таблицах: анонимные права уже отозваны,
  но изоляция вошедших пользователей не доказана для всех таблиц.
- В каталоге обнаружены другие anon-callable SECURITY DEFINER RPC. Сам факт
  EXECUTE не доказывает уязвимость: нужна проверка внутренних auth/membership
  условий. Их полная проверка не завершена.
- Storage, ограничения реального размера загрузки, публичность старых URL,
  push-провайдеры и внешние интеграции не прошли полный сквозной тест.
- Golden diff: просмотренная пара help_article сохраняет компоновку, но это
  не достаточное основание принять все 16 расхождений. Эталоны не заменялись.
- Проверка законов РФ и миграция инфраструктуры не закрываются тестами кода.

Независимый Codex review текущего пакета: APPROVE_WITH_NOTES, новых P0/P1
в локальных изменениях не обнаружено. Это не сертификат безопасности всего
продукта. Production deploy клиентского приложения не выполнялся.
