# Открыть Student Platform на Mac и проверить iPhone

Это исходники в отдельной ветке `codex/product-design`. GitHub не публикует приложение в App Store и не изменяет базу данных. Сборка по умолчанию может подключаться к рабочему серверу: используйте тестовый аккаунт и не отправляйте сообщения или файлы в реальные чаты без необходимости.

## Подготовка

Нужны macOS, Xcode с установленными компонентами и iOS Simulator, CocoaPods, Git и Flutter. Проверки этой ветки на Windows выполнялись на Flutter 3.47.2 / Dart 3.13.2. Минимальные версии зависимостей по `pubspec.lock`: Flutter 3.41 и Dart 3.11. Совместимость с установленным на Mac Xcode нужно подтвердить там командой `flutter doctor -v`.

```bash
git clone --branch codex/product-design https://github.com/mill196158-pixel/student_platform.git
cd student_platform
flutter doctor -v
flutter pub get
flutter precache --ios
cd ios && pod install && cd ..
open ios/Runner.xcworkspace
```

Открывайте именно `Runner.xcworkspace`. В Xcode выберите target Runner, затем Signing & Capabilities и свою команду Apple Developer. Текущий Bundle ID: `com.mill453020.studentplatform`; для уже существующего приложения он должен совпадать с App Store Connect. Минимальная версия iOS в проекте — 15.0. Доступы Apple, сертификаты, provisioning и APNs с этого компьютера не проверялись и в Git не помещаются.

## Проверка на телефоне

Подключите iPhone, разрешите доверие компьютеру и при необходимости включите Developer Mode. В Xcode выберите телефон как устройство запуска и нажмите Run. Либо после настройки подписи выполните:

```bash
flutter devices
flutter run -d <идентификатор_iphone>
```

Проверьте вход, список и открытие чатов, получение сообщений, ответы и пересылки, просмотр и загрузку вложений, ссылки, уведомления и возврат в приложение. Реальные отправки проверяйте только в согласованном тестовом чате. Отдельно проверьте push в development и TestFlight: итоговое `aps-environment` зависит от подписанного профиля.

## TestFlight и App Store — после проверки

Номер сборки в `pubspec.yaml` сейчас `1.0.0+18`; перед новой загрузкой в App Store Connect используйте номер build, который ещё не загружен для этой версии. Создайте Archive в Xcode или воспользуйтесь `flutter build ipa` после настройки подписи. Затем загрузите сборку в App Store Connect, проверьте её через TestFlight и только после этого отправляйте на проверку Apple. Инструкция: https://docs.flutter.dev/deployment/ios

## Известные ограничения текущей проверки

- Сборка и запуск iOS/macOS на реальном Mac не выполнялись; работу APNs, подписи и все ссылки пользовательского контента надо проверить на устройстве.
- Набор приложения и админки на Windows прошёл; часть эталонных визуальных снимков пакета `student_ui` отличается от текущего дизайна и требует отдельной сверки.
- SQL-миграции включены в исходники; Git не запускает их на сервере. Защита гостевого каталога от показа скрытых или архивных предметов применена к основной базе 5 ноября 2026 года: `20261105000711_guest_group_visibility_guard.sql`. Истории локальных и серверных миграций содержат расхождения: не запускайте массовое применение миграций без отдельной сверки, проверки состояния и резервной копии.
