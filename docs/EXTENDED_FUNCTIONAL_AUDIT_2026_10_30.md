# Расширенная проверка приложения — 29–30 октября 2026

## Итог и границы

Проверенные исправления готовы к локальной фиксации. Полная приёмка приложения **не завершена**: публичный доступ к объектам вложений остаётся P1-блокером выпуска, вложения формы сбора ещё не реализованы, сценарии учебных ролей и часть действий вложенных экранов требуют отдельных проверок.

Владелец разрешил основную базу. Изменения и тесты выполнялись на синтетических аккаунтах и чатах. Реальные сообщения/профили не удалялись. Схема изменена только новой миграцией идемпотентной отправки DM.

## Исправлено

- DM больше не делает второй прямой INSERT при ошибке получения уже отправленного сообщения. `send_dm_message_once` связывает ключ клиента с автором, чатом и полным payload. Повтор возвращает тот же ID; изменение payload отклоняется.
- Ожидающее сообщение сохраняет file IDs для повторной отправки. Завершение запроса после смены пользователя не записывает сообщение в кэш нового аккаунта.
- При сетевой ошибке загрузки `cleared_at` используется сохранённая граница очистки. Ошибка не запоминается как «история никогда не очищалась»; следующий запрос снова проверяет сервер.
- Пустые файлы и файлы больше 100 МБ отклоняются до полного чтения и сетевого запроса.
- Native OCR проверяет размер файла и размеры изображения до декодирования, ограничивает bitmap и освобождает ресурсы при исключении.
- Смешанный набор вложений больше не показывает полный список одновременно как картинки и документы. Убран ложный счётчик скрытых изображений.
- Форма сбора останавливает публикацию, если выбран файл, который серверный поток ещё не умеет сохранять. Введённые данные сохраняются; объяснение видно в форме. Это защита от потери файла, а не реализация загрузки.

## Незакрытый доступ к файлам

Прямой URL синтетического файла отдавал содержимое без авторизации. Проверка членства в `generate-upload-url` не закрывает чтение уже опубликованного объекта. Резервная копия policy/ACL сохранена вне репозитория; policy отсутствует (404), ACL возвращают 200 с пустыми списками grants. Параметры публичности бакета отдельно не подтверждены. Политики и публичность хранилища не менялись.

Нужно внедрить проверяемое получение временных ссылок, защитить происхождение `file_key`, учесть чувствительные подтверждения оплаты, перевести все просмотры/скачивание/пересылку/кэш и проверить ограничение на canary до применения ко всем `chats/*`. Старые APK используют прямые ссылки; простое закрытие всего бакета сломает их вложения.

## Уборка и изменения сервера

- Применена `20261029203453_idempotent_dm_send.sql`; существующий RPC отправки сохранён для совместимости.
- Синтетический объект удалён через подписанный DELETE: **204**, проверка подписанным GET: **404**.
- Временный `storage-access-audit` заменён автономным ответом **410**, без импортов и обращения к секретам; ответ проверен.
- Синтетические Auth-пользователи удалены. Повторная проверка: `users`, `chats`, `messages`, `chat_files` по fixture ID — **0 записей**.
- Временный файл с тестовыми паролями удалён, пароль убран из manifest.
- Обычная debug-сборка восстановлена и запущена на Android-эмуляторе после тестовых APK.
- Скрипт очистки теперь отказывается удалять fixture, если его S3-объекты ещё не подтверждены удалёнными.
