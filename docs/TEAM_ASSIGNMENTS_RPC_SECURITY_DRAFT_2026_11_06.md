# Draft: ограничение чтения get_team_assignments

Статус: локальный draft для review; к удалённой БД не применялся. Для применения требуется отдельное явно выраженное разрешение владельца с указанием проекта и объёма.

Read-only catalog audit подтвердил `public.get_team_assignments(uuid)`: SECURITY DEFINER, владелец postgres с BYPASSRLS; исходный WHERE ограничен team_id, EXECUTE был у PUBLIC, anon, authenticated и service_role. Нормализованный fingerprint `pg_get_functiondef` на момент проверки: `c278bc64bdcd0c88e849580c52d346e0`. Возвращаемый контракт содержит 19 полей; код миграции сохраняет их типы, порядок и исходную выборку.

Миграция добавляет проверку `auth.uid()` и прямого `public.team_members(team_id,user_id)`, как действующие live RLS-политики SELECT для assignments и teams, отзывает PUBLIC/anon EXECUTE, сохраняет authenticated/service_role EXECUTE и задаёт пустой search_path с квалифицированными именами. Результат для недоступной команды — пустой набор. Отдельный service_role без пользовательского UID теперь также получает пустой набор; требуется отдельно выяснить внешние сервисные вызовы до возможного применения.

Это проверка наличия текущей строки `team_members`, а не active enrollment. Не удалённые устаревшие членства и доступ к архивной команде продолжают работать так же, как в текущих RLS. Доступ только по совпадению `group_name` не добавляется: он не соответствует указанным RLS-политикам. В локальном репозитории найдены Flutter-вызов и integration test, упоминаний в исходниках локальных Edge Functions и в телах live public/private функций не найдено; это не доказывает отсутствие внешних клиентов, jobs или других версий Edge Functions.

Миграция проверяет fingerprint и точный набор owner/ACL до замены и эффективные права после неё; при расхождении транзакция отменяется. Это контроль дрейфа, а не гарантия отсутствия конкурентного DDL между проверкой и заменой: перед возможным применением нужны повторный read-only аудит и исключение параллельных изменений функции/ролей.

Rollback намеренно восстанавливает исходную уязвимость и EXECUTE для PUBLIC/anon; он имеет собственный fingerprint/ACL guard и не должен применяться к общей БД без отдельного осознанного разрешения владельца. Его исполнение в локальном fixture подтвердило восстановление исходного fingerprint и прежних EXECUTE grants.

`python scripts/test_team_assignments_security.py` запускает отдельный локальный PostgreSQL 16 на случайном порту 127.0.0.1 с синтетическими ролями и строками. Проверены anon, отсутствие UID, участник и чужая команда, teacher/admin с прямым членством, group-space, архив, оставшаяся и удалённая membership, service_role с UID и без него, сигнатура, rollback, mismatch fingerprint/ACL и наследование authenticated для anon. Сервер останавливается; папки одноразовых тестовых кластеров сохраняются в системном временном каталоге `student_platform_assignment_security_test`. Ранние локальные испытания оставили `supabase/local/assignment_security_test/`; эту папку нельзя включать в checkpoint.

Дополнительная граница membership: live `team_members` имеет включённый RLS и только SELECT policy, но действующий SECURITY DEFINER `join_team_by_code(text)` добавляет вызывающего пользователя в команду при предъявлении invite code. Следовательно, результат зависит от доверенности приглашений; полнота аудита косвенных writers и стойкость кодов остаются UNKNOWN. Включённый BEFORE trigger запрещает обычному пользователю менять собственный `group_name`, но уполномоченный `students.write` имеет административный путь. Пользователь без прямой строки, включая преподавателя, не получит задания. Табличный TRUNCATE также выдан anon/authenticated и не ограничивается RLS; возможность произвольного SQL под этими ролями не доказана и эта миграция её не меняет.
