ИНСТРУКЦИЯ: УЧЕБНАЯ АРХИТЕКТУРА STUDENT PLATFORM

1. Название предмета не является техническим ключом.
   Название используется только для отображения в UI.

2. Техническая связь предметов строится через subject_id.

3. Все новые названия предметов проходят через subject_aliases.
   Если приложение видит новое название, оно должно:
   - нормализовать строку;
   - проверить subject_aliases;
   - найти subject_id;
   - если совпадения нет — отправить в очередь ручного сопоставления.

4. Общий предмет хранится в subject_catalog.
   Пример:
   subject_catalog: "Математика"

5. Конкретный предмет у группы хранится в subject_offerings.
   subject_offering всегда должен иметь:
   - subject_id;
   - group_id;
   - academic_year_id;
   - semester_number;
   - curriculum_subject_id, если есть учебный план.

6. Команда создаётся только от subject_offering.
   Нельзя создавать команду просто по названию предмета.

7. Чат, задания, файлы и дневник всегда изолируются через subject_offering_id.
   Это защищает от смешивания разных групп.

8. Общая статистика предмета собирается через subject_id.
   Поэтому оценки старших курсов тоже попадают в общую статистику "Математики".

9. Частная статистика прохождения предмета собирается через subject_offering_id.
   Это статистика конкретной группы, конкретного семестра и конкретного преподавателя.

10. Преподаватель хранится отдельно в teachers.
    Его можно связывать:
    - с предметом вообще;
    - с конкретным subject_offering;
    - с конкретной группой и семестром.

11. Старый Flutter не ломаем.
    Старые поля остаются:
    - Team.name;
    - Team.teacher;
    - Team.groupCode;
    - users.group_name;
    - assignments.team_id.

12. Новые поля добавляются nullable:
    - group_id;
    - subject_id;
    - subject_offering_id;
    - academic_year_id;
    - semester_number.

13. Все новые функции делаем через RPC v2.
    Старые RPC не удаляем, пока приложение полностью не перейдёт на новую схему.

14. Основной принцип:
    "Один общий предмет — много реализаций для разных групп".


ИНСТРУКЦИЯ: ГРУППЫ, ПЕРЕВОДЫ И СЕМЕСТРЫ

1. Пользователь не привязан к одной группе навсегда.

2. История принадлежности студента к группам хранится в student_enrollments.

3. Активная группа определяется только через student_enrollments:
   status = 'active'
   ended_at is null

4. users.group_name остаётся только для совместимости со старым Flutter.

5. При переводе студента:
   - старая enrollment-запись закрывается;
   - создаётся новая enrollment-запись;
   - users.group_name обновляется;
   - users.primary_group_id обновляется;
   - студент добавляется в команды новой группы;
   - старые сообщения, задания, выполненные статусы и история не удаляются.

6. Нельзя удалять старые данные студента при переводе.

7. Команды новой группы создаются через subject_offerings текущего семестра.

8. Старые команды и чаты не должны смешиваться с новыми.

9. semester_number считается не из названия группы, а из:
   - admission_year группы;
   - academic_year.start_year;
   - academic_terms.term_in_year.

10. Название группы можно использовать только как подсказку и display.
